# MinecraftLauncher Architecture Cheat Sheet

> *Partially generated by AI*

Strict one-way dependency chain:

```
Launcher.UI.WPF (Presentation & Composition Root)
       │                    │
       ▼                    ▼
Launcher.Infrastructure (Desktop Client Services)
       │
       ▼
Launcher.Core (Domain & Game Launch Engine)
```

| Project | Responsibility | Allowed Project References | Allowed External Dependencies |
| :--- | :--- | :--- | :--- |
| **Launcher.Core** | Game domain, auth, process launch | *None* | BCL, `CmlLib.Core`, `XboxAuthNet`, `FluentResults` |
| **Launcher.Infrastructure** | OS I/O, app settings, themes, Discord | `Launcher.Core` | BCL, `DiscordRichPresence`, Zip/JSON tools |
| **Launcher.UI.WPF** | UI, MVVM, DI Composition Root | `Launcher.Core`, `Launcher.Infrastructure` | `CommunityToolkit.Mvvm`, WPF, Win32 APIs |

---

## Layer Rules

### 1. Launcher.Core (Domain & Launch Engine)
- **Scope**: Minecraft lifecycle only (auth, versions, instance folders, Java resolution, process execution).
- **Contracts**: Declares interfaces consumed by Core itself (`ILaunchService`, `IInstanceFileSystemService`).
- **Constraint**: Strict zero-UI policy; completely unaware of desktop-only features (themes, Discord, tray).

### 2. Launcher.Infrastructure (Desktop Client Services)
- **Scope**: Non-game desktop operations (settings persistence, theme parsing, localization, skin/icon cache).
- **Contracts**: Declares its own interfaces and DTOs (`ISettingsService`, `IThemeProvider`) consumed by UI.
- **Constraint**: Strictly pure .NET (no `System.Windows`, XAML, controls, or rendering types like `BitmapSource`).

### 3. Launcher.UI.WPF (Presentation & Composition Root)
- **Scope**: WPF views, MVVM view-models, UI state stores, and desktop window lifecycle.
- **Composition Root**: `App.xaml.cs` binds all DI modules (`AddGameServices()`, `AddAssetsServices()`, etc.).
- **Contracts**: Implements UI-bound services (`IFileDialogService`, `IClipboardService`, `IDispatcherService`).

---

## Architectural Guardrails

1. **Keep Core Pure**: Never import desktop shell features, themes, or UI packages into `Launcher.Core`.
2. **Zero WPF in Infrastructure**: Return raw paths, `Stream`, or `byte[]`; never reference `System.Windows`, XAML, or `BitmapSource`.
3. **Modular DI Registration**: Each module defines an `IServiceCollection` extension method (`AddGameServices()`, `AddAssetsServices()`); `App.xaml.cs` only invokes these top-level calls.
4. **Reliable Offline Fallback**: Probe `IConnectivityService` before networking, use local caches, and never swallow network exceptions when local files are missing.
