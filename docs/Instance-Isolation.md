# Instance Isolation Types: Purpose and Mechanisms

## How Game File Storage Works

Historically, all game files have been stored in a single shared directory located at `%AppData%\.minecraft`. This approach was traditionally used by the official Minecraft launcher and many third-party clients (such as Legacy Launcher, SKLauncher, and MRLauncher). In this setup, all game versions and mod loaders share the exact same saves, mods, resource packs, and a single `options.txt` configuration file.

Over time, launchers such as MultiMC, Prism Launcher, CurseForge, and the Modrinth App popularized the "instances" approach. The core idea is to allocate an independent directory for each game version or modpack, ensuring that files from different versions do not conflict with each other, reset settings, or corrupt worlds. In the official launcher, this can only be achieved manually by reassigning the game directory within profile settings.

In this launcher, you can choose the desired isolation type when creating a new instance.

> **Note:** The isolation type is set strictly during instance creation. It cannot be changed later for any instance.

---

## 1. Global Isolation

The instance uses the standard root `.minecraft` folder. All saves, resource packs, mods, and settings remain shared across all versions using this mode.

**Best suited for:** Pure Vanilla versions where having seamless, constant access to the same worlds and settings without unnecessary file duplication is convenient.

---

## 2. Full Isolation

A completely autonomous folder is created for the instance, containing its own saves, mods, configs, and game settings.

**Best suited for:** Heavy modpacks with deep gameplay changes and unique configurations. This is the standard and safest choice, recommended by default for all mod loaders.

---

## 3. Partial Isolation

*(Unavailable for Vanilla instances, as it serves no purpose without mods).*

The launcher creates a separate instance directory with its own isolated `mods` folder, while establishing symbolic links (symlinks) to key shared components from the global `.minecraft` directory:
- Directories: `saves`, `config`, `resourcepacks`, `shaderpacks`, `schematics`, and `screenshots`
- Files: `options.txt` and `optionsof.txt`

All other files and directories created by the game or mods during runtime (for example, map tile caches generated by mods like Xaero's World Map) are stored strictly inside this instance's folder.

As a result, the installation gets its own isolated set of mods while preserving access to shared worlds, textures, keybinds, and client mod settings that rarely change across versions. This option is ideal for client-side modpacks and lightweight mod configurations.

> **Important:** This mode is designed for experienced users. Creating symbolic links on Windows requires elevated privileges; therefore, during instance creation, the launcher will automatically request Administrator confirmation (UAC) via a helper process.
